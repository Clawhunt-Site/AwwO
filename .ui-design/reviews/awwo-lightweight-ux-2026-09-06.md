# AwwO 轻量体验方案

2026-09-06 · 设计提案 · 基于 acceptance.5 实际页面和当前源码

## 建议先做什么

保留“每个节点是独立 Agent 和 Session”的产品核心，把日常操作收敛为：**说清目标 → 看懂分工 → 进入节点对话 → 拿到交付物**。

当前已经支持总览卡片和单节点展开，方向成立。下一轮优先解决展开后读什么、下一步点什么、运行前要配置什么。先做聊天可读化、草稿修复、聚焦工作台和结果入口，再做批量准备与可下载的真实交付。

“轻量”的验收口径是减少必须做出的决定、减少重复阅读、减少来回切换；保留按需展开的输入输出契约、历史 Session、运行细节和人工调整能力。

## 审视范围与证据

- 实际走查 `http://127.0.0.1:15188/` 的两节点验收画布、展开节点、三个 Session、交付物、画布助手、运行反馈、配置和个性化模板库。只切换展示，没有发送新任务、绑定节点或修改服务器数据。
- 对照 `CanvasSurface`、`SessionTile`、`CanvasAssistant`、`InspectorPanel`、`NodeDeliverables` 和消息恢复链；保留当前未提交的服务验收增量。
- 首次空白画布流程依据当前源码审查，本轮没有重建空白工作区。运行中行为结合上一轮实测及当前源码，不将静态审查冒充新一轮功能测试。
- 这是专家走查和设计建议，尚未进行外部用户可用性研究。下文的点击数和成功率是下一轮验收目标。
- 参考方法：次要能力按需展开、保持状态可见、减少用户记忆负担。这些来自 [NN/g 渐进呈现](https://www.nngroup.com/articles/progressive-disclosure/) 与 [可用性启发式](https://www.nngroup.com/articles/ten-usability-heuristics/)。具体取舍来自本产品的实际路径。

## 当前最影响体验的地方

| 优先级 | 实际发现 | 对用户的影响 | 建议 |
| --- | --- | --- | --- |
| P0 | 聊天中的用户消息包含整段工作流、输入字段、输出格式；Agent 回答直接显示 `result/followups` JSON | 一句需求被长文本淹没，用户难判断 AI 到底交付了什么 | 默认呈现原始用户意图和可读回答，契约与原始事件放“执行详情” |
| P0 | 当前成功消息仍留在输入框；源码确认运行标记先设置，后续持久化草稿清除被拦截 | 刷新后像未发送，容易重复执行 | 用已接受操作的身份消费对应草稿，保留之后输入的新草稿 |
| P0 | 生成画布与真正能运行之间存在逐节点选择 Runtime、公司、绑定和保存的断层 | 看似已生成完成，实际上还需要理解底层配置 | 工作区确认一次默认执行环境；首次运行集中补齐缺失项、连接必要节点 |
| P1 | 项目助手、节点聊天、运行按钮、底部范围按钮、更多菜单并存 | 用户不确定是在改整个结构，还是让当前 Agent 干活 | 明确项目与节点两个作用范围；同一时刻只突出当前范围的输入 |
| P1 | 工作台仍在变换后的画布中缩放；实际页面留有大量空白，节点内对话和交付各自滚动 | 读文字、看关系、操作节点互相牵制 | 点开节点后在画布工作区聚焦，正文按屏幕尺寸排版；返回时恢复原画布位置 |
| P1 | 运行控制、节点完成、连接状态、恢复提示及时间线同时表达状态 | 1/1 成功与两个节点并存时不易理解执行范围 | 项目显示本轮范围和进度，节点显示自身状态；历史提示归档到运行记录 |
| P1 | 节点运行时“查看交付物”也被 busy 锁禁止 | 用户只能等待，无法核对已完成的工作 | 运行时允许只读查看和复制旧交付，编辑、发布及改变活动 Session 仍受约束 |
| P1 | 文件交付主要是路径；当前实现明确不读取文件 | 用户看到“有交付物”，仍不知道如何实际打开或取走 | 建立真实产物引用后提供预览/下载；在此之前准确显示“文件路径” |
| P2 | 添加模板先展示完整输入输出、工作步骤和标准，节点中又有模板指南 | 第一次有解释价值，重复添加时成本偏高 | 选择时只给职责、输入、交付和添加；个性化体现在实际表单与成果视图 |
| P2 | “账号与工作区”“我的工作区”“公司”“ClawHunt 账号”分属不同层 | 容易误解当前画布归属、权限及执行身份 | 显示真实归属；成员管理选择器与画布切换明确区分 |

这些是排序后的体验问题，不代表全部属于代码缺陷。草稿回填已有代码因果；文件下载、统一默认执行环境和项目归属需要补产品能力。

## 方案结构：一个项目，两个工作层级

### 项目总览

顶栏只承担项目名称、当前工作区、成员和项目设置。主体是 Agent 分工图。页面主操作根据状态在“开始执行”“停止执行”“查看交付”之间变化。

每张节点卡默认只展示四类信息：名称与职责、一条状态、最新可用成果摘要、打开节点的入口。保留现有单节点展开机制，不增加“简单版/专家版”等永久模式选择。

连线默认表达实际依赖。选中一条线时再展示“数据规则 · 数据字典 → 用户服务 · 数据模型”以及字段映射。连线依然是精确字段关系，视觉上不能简化成无法判断方向的装饰线。

项目助手收为明确的“调整整个项目”入口。展开时显示项目需求及本次结构变更；退出后恢复分工图。节点对话不会同时作为另一个主要输入框吸引注意。

现阶段项目侧栏可以只保留当前画布与节点目录。多项目导航属于后续能力；交互原型中的项目名称不代表当前已支持跨设备项目同步。

### 节点工作台

点击节点，工作区聚焦到这个组件；保留节点身份、输入输出和返回画布入口。画布其他节点不在背后与对话争抢视线，原始节点坐标不因聚焦而被修改。

| 区域 | 默认内容 | 按需展开 |
| --- | --- | --- |
| 节点顶栏 | 返回画布、节点名称、一条状态、交付物、设置 | 本次执行范围及详细记录 |
| 左侧 | 当前会话名称；多个会话时可展开列表 | 历史会话、重命名、新会话 |
| 中间 | 用户原话、可读回答、明确下一步、输入框 | 本轮引用、工具执行及原始消息 |
| 右侧 | 默认收起；点击交付物打开最新成果 | 历史版本、输入来源、字段契约 |

聚焦节点时全局导航收窄，避免两个完整左栏常驻。单个会话时不强迫用户管理列表；仍保留显式的会话入口。默认名称来自任务内容，例如“会员权限设计”，并可手动改名，底层 Session ID 保持不变。

正文按屏幕像素显示，建议 14–16px；图的缩放只影响总览。窄屏用同一节点内的“对话 / 交付物”切换，历史会话用弹层选择；保留结构列表作为复杂连线的替代阅读方式。关闭工作台后回到之前的画布位置。

## 从输入目标到交付的完整路径

### 1. 开始一个项目

首屏中心只有一个主要输入：“你想完成什么？”给少量具体示例，例如“做一个带会员权限的后台”。模板与空白开始放在次级入口。

AI 根据需求提出必要分工、输入来源和成果。通常先用少量节点起步，节点数量随任务增加；不强制每次创建前端、后端、用户、数据、物料、验收七个节点。已确定的底层接口和数据约定作为项目内可复用的基础，避免每次重新发明。

只有影响正确执行的缺失信息才提问。可合理推断的选项列为“已采用的默认项”，用户可改。画布方案的生成与节点的真实运行分别表达，不把草案标为完成。

### 2. 确认分工并准备执行

“应用方案”创建或修改画布，随后“开始执行”进入一次集中准备：

- 已登录且已授权的 Codex 环境直接复用；明确显示当前可用环境，不要求每个节点重复登录。
- 已存在的节点绑定保持不变。新节点使用已确认的工作区默认值，并保留单节点覆盖能力。
- 展示缺少的必填输入，例如“前端还需要页面范围”，点击即可补充。
- 系统创建独立 Agent、工作目录和首个 Session；有错误时按节点展示，可继续处理未完成部分。
- 模型及思考强度读取实际目录。更换访问权限或执行身份必须可见；“默认继承”不等于扩大权限。

成熟路径的目标是“输入需求 → 应用分工 → 开始执行”，在环境和输入齐备时不再逐节点开配置。

### 3. 执行与纠正

运行按钮旁显示范围，例如“整个项目 · 4 个节点”。范围菜单保留：整个项目、仅当前节点、从此节点继续。单节点聊天仍只派发该 Agent，不暗中触发后续节点。

运行期间默认显示“用户服务正在执行，前端等待接口契约”。只有需要追查时才打开时间线、模型信息、原生运行记录。用户可以打开旧交付和只读历史；修改输入、结构、绑定和发布等行为仍按实际执行约束处理。

改变已被下游使用的内容时，提示影响：“此修改影响前端和验收两个节点”，允许更新受影响部分。上游结果如果被复用，应标注版本与来源，不伪装成重新执行。

### 4. 拿到结果

完成后主操作变成“查看交付”。交付视图优先呈现可使用的内容：页面预览、文件、文档和验证结果；点击具体成果可追溯来源节点、会话、运行和版本。

继续与 Agent 讨论不会自动替换已供下游使用的正式交付。新结果通过契约校验后才可采用；用户编辑的输出标明“人工调整”，并显式选择“采用并更新下游”。

## 对话怎么变得像对话

用户看到：“补充管理员和普通会员的权限区别。”

Agent 回答：“已补充两类角色权限，新增 6 条访问规则。你可以在交付物里查看权限表。”下方是一张实际交付引用，可打开权限表；没有真实交付时显示尚未生成。

执行时需要的角色说明、上游资料、富文本契约、JSON 规范仍然传给 Agent，但放进“本轮输入与执行详情”。默认回答渲染经校验的结构化内容，不直接倾倒 JSON。

实现上增加用户可读的消息投影：原始用户文本、实际执行文本、操作标识、原生评论/运行标识、交付引用分别保存并精确关联。恢复历史时读取同一关联，不能只在发送当下美化，刷新后又退回原始文本。

对于旧历史，只有存在可信关联时才恢复原始用户文本；其余作为“历史执行消息”折叠保存。不要用正则在任意文本里剪掉看起来像系统提示的段落，避免误删用户内容。

输出解析失败时保留原始信息并显示“结果格式需要修复”，不伪装成成功。重复消息按已确认的原生标识去重，不能按相同正文去重，因为用户可能确实重复发出同一请求。

草稿清除以服务端确认接收的操作为准，只消费该操作提交的文本版本。刷新前后、不同 Session 之间以及后续新输入都应独立，失败或未确认请求的草稿继续保留。

## 保留模板个性化，减少模板说明

| 模板 | 首先向用户要什么 | 优先呈现什么交付 | 个性化快捷动作 |
| --- | --- | --- | --- |
| 前端开发 | 页面目标、接口来源、设计参考 | 页面预览、修改文件、交互检查 | 调整布局、检查移动端 |
| 后端服务 | 业务规则、数据约定 | 接口说明、变更和验证结果 | 补充接口、检查异常路径 |
| 数据治理 | 数据来源与需要统一的定义 | 数据字典、质量问题与处理规则 | 补充字段、核对来源 |
| 用户系统 | 角色、权限、登录需求 | 权限矩阵、账户流程、权限检查 | 增加角色、核对越权 |
| 物料制作 | 受众、渠道、规格 | 可用素材、版本及使用说明 | 改文案、调整渠道规格 |
| 交付验收 | 验收范围与标准 | 逐项结论、失败项和证据 | 复验失败项、追溯来源 |
| 自定义 Agent | 目标、输入、完成标准 | 对应任务的成果和未完成项 | 补充要求、继续当前任务 |

表中交付是模板设计要求，不代表自动拥有相应服务、预览器或已验证成果。复杂表单结构和完整工作说明继续保留在模板详情与节点设置。

## 统一状态，但不丢失真实语义

| 用户看到 | 应当成立的事实 | 对应操作 |
| --- | --- | --- |
| 待开始 | 未派发，准备完整 | 开始执行 |
| 需要补充 | 缺少输入或真实执行环境 | 补充指定项 |
| 等待前置结果 | 依赖未满足，自身未执行 | 查看等待谁 |
| 执行中 | 存在确认的活动运行 | 停止执行、只读查看 |
| 正在停止 | 已请求停止，仍待原生确认 | 查看停止进度 |
| 已停止 | 原生取消已确认 | 沿用当前会话继续 |
| 正在核对 | 连接中断、终态或结算不确定 | 重新核对；不重复派发 |
| 需要处理 | 实际错误或交付未通过 | 针对原因修复 |
| 已完成 | 实际执行、结算和交付校验确认 | 查看交付 |

“完成”属于具体运行范围，不能把聊天一次成功当整个项目成功。人工暂停单独显示“人工暂停中”，不得当成可自动解除的普通等待。旧完成结果保留“上次交付”的时间与版本，与当前失败或运行状态并存时不互相掩盖。

## AI 调结构与人工调整共用一份画布

“给这个项目补上用户系统”先生成变更预览，标出新增节点、改动连线、需要更新的成果和保留的会话。用户应用后才改结构；执行另有明确入口。

可撤销的布局和名称调整保持轻便；删除节点、重新绑定、改输入输出契约等可能影响历史和交付的动作，显示具体影响并保留恢复路径。AI 修改使用真实图的版本检查，不覆盖期间的人工作业。

人工操作保留添加节点、连接字段、调整布局、重命名、删除、撤销和快捷键。默认隐藏端口细节时，选择节点或进入“连接”操作应能通过键盘完成同样的字段映射，不让关键能力只能靠鼠标悬浮发现。

## 落地顺序

| 阶段 | 交付范围 | 完成后用户能感受到什么 | 依赖 |
| --- | --- | --- | --- |
| 第一批：降低阅读与操作负担 | 原话/执行文本分离、可读结果、草稿消费修复；助手按需打开；聚焦节点；交付只读可达；执行范围明示 | 一进节点就能读懂对话、知道下一步，并能放心刷新 | 现有持久化、原生身份和状态机，补相关回归 |
| 第二批：降低首次配置负担 | 已确认执行环境继承、集中准备、缺失项定位、模板快捷添加 | 生成画布后可以顺畅进入真实运行 | 绑定幂等、真实目录、工作区权限归属 |
| 第三批：让结果容易取用与迭代 | 受控产物预览/下载、交付版本、AI变更影响预览、更新受影响节点 | 找得到、拿得走，改一次不用全项目重来 | 产物身份与访问接口、图版本和依赖失效规则 |

先完成第一批并复测，再决定是否调整整体视觉。第一批不依赖新的多租户架构；第二、三批需要真实服务能力，不能只增加按钮或改文案。

## 体验验收目标

1. 已有可用 Codex 环境时，首次运行不重复登录、不逐节点选择公司和模型；准备齐备的示例只需输入需求、应用分工、开始执行三个主要步骤。
2. 从卡片到节点对话一次点击；从节点到最新交付再一次点击。运行中同样可只读查看已有交付。
3. 默认对话不暴露系统组装提示或原始 JSON；原始内容仍可通过详情追溯。旧消息安全降级，不丢正文。
4. 发送已确认后刷新不重新出现已消费草稿；真正未发送的新草稿保留。恢复后每条实际消息只呈现一次。
5. 用户随时可辨认操作作用于整个项目还是当前节点；单节点运行不会被悄悄扩大为整图执行。
6. 停止未确认时保持“正在停止”；不确定状态先核对；人工暂停不会被 AI 静默解除。
7. 修改上游后明确受影响节点和旧成果来源；不会把未校验或历史输出自动传播。
8. 在常见桌面宽度和窄屏下正文可读、主操作不被时间线覆盖；键盘能打开节点、切换面板和返回画布。
9. 文件下载按钮只对有真实受控引用的产物出现；缺失、无权限、生成中有独立反馈。
10. 找 5 位未参与开发的目标用户，独立完成建图、运行、查看结果、改一个要求、恢复一次中断。目标至少 4 位无需讲解完成主要路径；记录卡住的位置再迭代，不以演示顺利代替验证。
