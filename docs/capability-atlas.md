# Capability Atlas

The capability atlas embeds the full capability profile of the OpenClaw/ClawHunt ecosystem
into SuperClaw as one queryable, typed registry. It catalogs every capability unit the
agent can draw on — skills, plugins, tools, and services — with provenance and an
availability grade, so planning consults a real inventory instead of folklore.

## Data model

Each unit in `packages/superclaw/src/superclaw/capability_atlas.json` carries:

| Field | Meaning |
| --- | --- |
| `id` / `name` | Kebab-case unique id (usually the skill or plugin directory name). |
| `category` | One of 12 fixed categories (engineering, security, data-analytics, media-generation, marketing-seo, productivity-workflow, agent-orchestration, knowledge-research, platform-integration, finance-trading, communication, self-improvement). |
| `origin` | Where it comes from: `self-built`, `wshobson-arsenal`, `openclaw-builtin`, `external-oss`, `external-service`, `tool`. |
| `source_url` | Canonical upstream location. |
| `description` | What it does and when to use it. |
| `triggers` | Keyword phrases used by `suggest` to match goals to capabilities. |
| `integration` | `skill`, `plugin`, `tool`, or `service`. |
| `availability` | `vendored` (source mirrored in our catalog repo), `local` (source on this machine), `external` (upstream/network dependency), `declared` (cataloged but no source found — a gap). |

The loader fails closed: unknown categories, integrations, availabilities, duplicate ids,
or a missing data file raise `CapabilityAtlasError` instead of degrading silently.

## Surfaces

CLI (`superclaw capabilities …`):

```powershell
superclaw capabilities summary
superclaw capabilities list --category engineering --availability vendored
superclaw capabilities show adversarial-verification
superclaw capabilities search "seo"
superclaw capabilities suggest "ship a payment webhook with idempotent capture"
superclaw capabilities coverage
superclaw capabilities matrix
superclaw capabilities adaptable --target codex
superclaw capabilities doctor
```

API (same data, no auth required — read-only metadata like `/api/harnesses`):

- `GET /api/capabilities?q=&category=&origin=&availability=&integration=`
- `GET /api/capabilities/{id}` (404 with known-id hint on miss)
- `GET /api/capabilities/coverage`
- `GET /api/capabilities/suggest?goal=&limit=`

Python:

```python
from superclaw.capability_atlas import suggest_capabilities, coverage_report

plan_hints = suggest_capabilities("render a product launch video with captions")
gaps = coverage_report()["declared_gaps"]
```

## How it strengthens delivery runs

- **Goal intake**: `suggest_capabilities()` ranks units by trigger-phrase hits against the
  goal text, so run planning starts from the ecosystem's actual capability profile.
- **Harness portability**: units with `integration` in `{skill, plugin}` and availability
  `vendored`/`local` are flagged `adaptable` — they can flow through the existing
  `superclaw harness adapt-skill` / `harness emit` pipeline into codex, cursor, opencode,
  or gemini artifacts.
- **Honest coverage**: `coverage_report()` separates what is actually on disk from what is
  merely declared upstream. `declared` units are a vendoring backlog, not a capability.

## Maintenance

The catalog is regenerated by scanning the sources (the `openclaw-arxchibo` skills repo,
the wshobson `agents` plugin tree, OpenClaw built-ins, and the external links in the
all-skills manifest) and merging by id with availability priority
`vendored > local > external > declared`. After any regeneration, run:

```powershell
superclaw capabilities doctor
python -m pytest tests/test_capability_atlas.py
```
