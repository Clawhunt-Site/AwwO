# 画布融合决策文档 — 以哪个为基座 · 搬哪些优点 · 冲突怎么处理

> 本文回答三件事：**① 以哪个项目为基础改；② 另一个项目的哪些优点搬进来；③ 加功能撞车时怎么处理。**
> 不是空泛方法论 —— 每条都对应 2026-07-22 这次会话真实做过的决策与 PR，可复查。
>
> 涉及的两个项目：
> - **SuperClaw canvas**（我们自己的，`ClawHunt-Store/SuperClaw-canvas`）= React/TS 的 **agent 编排画布**（公司 / agent / mission / 创意节点 / 时间线），已上线、已接真实公司+relay。
> - **Infinite-Canvas**（`github.com/hero8152/Infinite-Canvas`）= Python 后端 + 原生 JS 前端的 **AI 图/视频生成中枢**（ComfyUI 节点、图像扩展、360 全景、视频抽帧）。
>
> 另外，舰队画布（Fleet）↔ 创意画布（Creative）→ 融合 Studio 的内部融合，作为「冲突处理」的第二组实战例子贯穿全文。

## 一、以哪个项目为基础进行修改 → **以 SuperClaw canvas 为基座**

结论：**用我们自己的 SuperClaw canvas 当基座，Infinite-Canvas 只当「优点供体」，绝不反过来**。

判据（任一项都指向同一结论，不是感觉）：

| 维度 | SuperClaw canvas | Infinite-Canvas | 谁当基座 |
|---|---|---|---|
| **是否现役事实源** | 是，商业产品线上主干（apps/web + vendored Node server + gateway），已上线、4 家真实公司、relay 真实扣费实证 | 否，第三方独立项目 | **我们** |
| **技术栈** | React 19 + TS + Vite，现代、类型安全 | Python 后端 + ~1.5MB 原生 JS 前端，异构 | **我们** |
| **工程基建** | 800+ 自动化测试门、CI、Cloud Run 部署流水线、fail-closed 治理门 | 无可复用的对齐基建 | **我们** |
| **许可证** | 我们自有，可商用 | 非开源、**禁商用** + **传染性开源**（GitHub 识别 NOASSERTION），拿来当基座会强制 ClawHunt 开源 | **我们** |
| **产品域契合** | 就是 agent 编排画布本身 | 图/视频生成中枢，95% 与我们无关 | **我们** |

一句话：**基座要选「现役 + 同产品域 + 技术栈可持续 + 许可证干净 + 有测试/部署基建」的那个。** 五项全中的是我们自己的画布，所以 Infinite-Canvas 无论如何都只能当供体，不能当底座。

> 反面教训（写清以免日后纠结）：许可证是**硬阻塞**。业主即使声称「对那个 repo 有授权」，禁商用 + 传染开源的条款仍意味着**不能把它的代码搬进商业产品**——最多合法借鉴「通用交互概念」（见第二节）。

## 二、另一个项目（Infinite-Canvas）的哪些优点需要加进来

> **状态更新（2026-07-22）**：业主与 Infinite-Canvas 作者为**商业合作关系，授权已处理干净** —— 第三节 ① 的许可证阻塞解除。策略从「只抽通用 UX 原语自实现」升级为「**直接对应移植其前端交互层**」（忠实移植语义 + 确切常量；因技术栈异构（原生 JS → React/TS），落地形态是移植而非逐行照抄）。产品域功能（图/视频生成）仍不搬 —— 与 agent 画布无关。

### 2.1 已搬进来的（真正可转移 + 有价值）

| 优点 | 现状 | 怎么搬的 |
|---|---|---|
| **触摸 pinch-zoom（双指捏合缩放）** | ✅ 已上线（PR #32） | 它的 `touch-mouse.js` 把 pinch→缩放。我们的 `CanvasViewport` 用 Pointer Events、单指 pan 已覆盖、但缺两指捏合。→ 在我们的 viewport 上实现：第二指进 pinch、按指距比缩放锚定中点、同时按中点漂移平移、抬起一指交回单指 pan。**保留我们的连续版**（上游是量化 ±100 tick、不随中点平移——我们的更好）。 |
| **指数滚轮缩放曲线**（核心件） | ✅ 已上线（PR #36） | `exp(-ΔY·unit·0.0008·mac1.15)`，line=40px、page=视口高。替换固定 1.1/格：鼠标一格 ~1.083×，触控板小 delta 成比例细腻缩放。**顺便解掉"trackpad-pinch vs Ctrl+滚轮无法区分"** —— 上游根本不看 modifier。 |
| **中键平移** | ✅（PR #36） | button 1 pan + preventDefault 压掉浏览器自动滚动。 |
| **didPan 门控**（pan-vs-click 判别） | ✅（PR #36） | >3px 曼哈顿（鼠标）/ >10px（触摸，浏览器 tap slop 内的手指抖动不能吃掉双击建司）标记为 pan，随后 180ms 内抑制背景双击 —— 修掉"拖完误建公司"。 |
| **Z 键 overview toggle** | ✅（PR #36） | 存视口 → 全景 fit（pad 160 world / margin 80 screen / clamp [0.06,0.82] / 空画布 0.45）→ 再按 Z 还原。上游"点节点退出并放大到该节点"**刻意不搬**：他们的节点是图片，我们的是密布按钮的卡片，capture 层拦截会偷走 hire/chat/dispatch。 |
| **Minimap** | ✅（PR #36） | 节点∪视口 ±200 world pad、节点点 ≥4×4、视口框 ≥8×8；点=跳转居中、拖=scrub（绝对定位）、**永不改 zoom**。 |
| **边双击断开**（conn-hit） | ✅（PR #36） | 12px 隐形 hit stroke + dblclick 断线（单击不断，防误触）。 |
| 缩放范围 | ✅（PR #36） | 上游无界（仅有限性守卫）→ 我们放宽 [0.2,2.4]→[0.05,4] 但**故意保留 clamp**（无界画布会迷失）。 |
| **设计状态（视觉层）** | ✅（PR #38） | 12 令牌两套主题逐字搬(`--page/--grid/--panel/--card/...`,挂到宿主 `data-theme`)、24px 屏幕固定点网格、chromeless 卡片语言(实底 var(--card)+16px+软长影+hover 转 --strong 描边)、玻璃 chrome 三档配方(blur 16-20 + 影 34/44/58)、Inter 重字重微字号、pill 优先圆角。**世界内不用 backdrop-filter**(他们的 .canvas-scaled 守卫,我们按构造满足)。 |
| 惯性滚动 | 不存在 | 逐域源码审计确认**上游也没有惯性**（无 lerp/momentum/rAF 动画）——忠实对应=不加。 |

### 2.2 评估过但**不搬**的（明确记录，免得反复评估）

- 图/视频生成、ComfyUI 节点图、360 全景、视频抽帧、循环节点 —— **它的产品域，与 agent 画布无关**，搬进来是纯负担。
- 它那 `smart-canvas.js` 860KB + `canvas.js` 709KB ≈ 1.5MB 原生 JS —— 整体 port 既不可能（技术栈异构）也无价值。

### 2.3 可选的后续小优点（如需要再做，非阻塞）

- 双击空白处 **fit-to-content**（缩放到全部内容）
- 触控板 **Ctrl+滚轮 比例缩放**（更细腻的缩放手感）
- 惯性滚动（inertia）—— 视体验需求，可加可不加

> 判据：**「这个优点是通用交互体验，还是它的产品功能？」** 是前者才搬（且重实现，不照抄）；是后者一律不搬。

### 2.4 顺带：舰队↔创意的优点已互相融进 Studio

同一原则也用在内部两块画布上——把各自的**头牌能力**搬进融合 Studio 一块画布：
- 舰队的 **mission 跨公司规划 + 派发**（PR #33，`StudioMissionPanel`）
- 创意的 **多轨时间线 NLE**（PR #34，`StudioTimelinePanel`）

## 三、加功能的时候冲突了怎么处理

融合/加功能时的冲突分七类，每类给**判据 + 这次真实怎么处理的**。

### ① 许可证冲突（最高优先级，硬阻塞）
- **判据**：动手前先看对方 `LICENSE`。禁商用 / 传染性开源 / NOASSERTION = **不能把它的代码搬进商业产品**。
- **处理**：把阻塞**摆给业主决策**，不擅自越界。合法路径是**只借鉴通用 UX 概念、自己重实现**（交互模式不受版权保护，具体代码受保护）。
- **实例**：Infinite-Canvas 禁商用 + 传染开源 → 不抄它任何代码，只把「双指捏合缩放」这个通用手势在自己的 viewport 上重写。

### ② 技术栈冲突
- **判据**：异构技术栈（Python + 原生 JS vs React/TS）之间**不 port 代码**。
- **处理**：把对方的**行为/交互重实现**成本项目的原生组件，复用本项目已有的纯函数（如 `zoomAt()`）。
- **实例**：pinch-zoom 用 Pointer Events 重写，而非移植它的 `touch-mouse.js`。

### ③ CSS / 主题冲突
- **判据**：两套样式合到一块画布，最容易撞的是**全局类名**和**CSS 变量作用域**。
- **处理**：用**作用域包裹**让变量解析、又不泄漏进宿主主题；避免 `:root` 全局变量泄漏。
- **实例（M3 教训）**：创意时间线的 `cc-*` 类是全局的、但它读的 `--cc-*` 变量 scoped 在 `.creative-app`。把挂进 Studio 的时间线用 `<div class="creative-app">` 包一层 → 变量解析、像素级一致、且**不污染** studio 自己的 `.studio-*` 主题。舰队早期的 `:root` 泄漏也是同类问题，靠收窄作用域解决。

### ④ 状态耦合冲突（决定「怎么搬」的关键）
- **判据**：先看被融组件的**耦合度**——是干净可复用组件，还是深绑宿主状态机？
- **处理**：
  - **干净可复用组件 → 直接挂。** 如 `TimelinePanel`（`{initialDoc, onChange}` 自管历史）→ 直接挂进抽屉，还共用同一个 localStorage 文档，不分叉。
  - **深耦合状态 → 不要 re-host，只复用它底下的纯函数、自建 UI。** 如舰队 `Inspector`（深绑 `fleet-canvas/App` 的 mission/批量/活动流状态）→ **不搬整套状态机**，只复用它底下的纯网关客户端函数（`planMissionViaGateway` / `dispatchTrackViaGateway`），包成 Studio 原生的 `StudioMissionPanel`。
- **实例**：PR #33（Inspector：复用纯函数自建）vs PR #34（TimelinePanel：直接挂）——同一节课的两种答案。

### ⑤ Git 集成漂移 / 合并冲突
- **判据**：多分支并行、各自基于不同 base，后合的没吸收先合的改动 → 合入后撞车。
- **处理**：合并前 `git fetch` 把 `origin/main` 吸收进分支 → `merge --no-commit` 解冲突 → 在解冲突结果上跑**相关测试全绿** → 顾问对抗验收无阻断 → 才**原子提交**（一个 commit 一件事，可独立回滚）。共享主干**绝不 force-push**。
- **实例**：本次每个增量都是独立分支 → PR → 合并 → 同步 main → 部署，串行不重叠，避免两个部署抢流量。

### ⑥ 语义 / 诚实冲突（fail-closed）
- **判据**：新功能接真实后端时，**失败绝不能伪装成成功**，**没有真实后端时绝不给假动作入口**。
- **处理**：
  - 规划失败 → **显式报错**，绝不给一个「看着能用的空计划」让人派发进虚空（`planMissionViaGateway` 失败即 throw → 面板报错）。
  - 派发 → 只渲染**真实 outcome**（dispatched / queued / no_agent / error），成功回调只在真派发时触发。
  - **只在 live 世界**显示 mission 规划（demo 世界没有真公司可派，给了就是 false affordance）。
- **实例**：`StudioMissionPanel` 全程人审、诚实门齐备；这是承接项目既有的「fail-closed 治理 / 表层零伪造」铁律。

### ⑦ 决策优先级（撞车时按什么排序）
```
项目现有规范 > 相关最佳实践 > 语言/框架约定 > 行业标准 > 合理默认
```
- 命名 / 代码风格 / 目录 / 依赖版本这类 → **自行决策**，不问。
- **许可证 / 不可逆 / 安全 / 架构级对立选型** → 先问业主，不擅自定。

## 附：融合执行纪律（checkpoint，防「一把梭」）

**分增量做，每个增量独立走完整闭环：**

```
写代码 → 相关+全量测试绿 → build → 顾问对抗验收 → 原子提交 → PR → 合并 → 同步 main → 部署 → 浏览器线上实测
```

- 大特性**绝不**一把梭成一个没法评审的巨改。
- 每个增量可独立上线、可独立回滚。
- **线上实测**才算完成（「编译通过」≠「完成」）：本次两个增量都在公开 URL 上验证过面板真的展开、真的渲染。
