# AwwO v0.3.2 pre-release verification

## Status and source boundary

This is a pre-release record. Every check below remains pending until its result is added from direct evidence. This document does not claim that tests or reviews passed, that a tag or release was created, or that any server was changed.

The candidate starts from exact base commit `fc5cbda9e4028837009369471ec2d54b94a985a5` (AwwO v0.3.1) in an isolated detached worktree. The intended v0.3.2 scope is limited to invitation-credential redaction in request logs and a validated, pre-construction `AWWO_LOG_LEVEL` setting. Credentials, runtime state and database content are outside the source change.

`AWWO_LOG_LEVEL` accepts only `fatal`, `error`, `warn`, `info`, `debug`, `trace` and `silent`. An unset or whitespace-only value defaults to `debug`, preserving existing behavior. Validation must happen before the log directory, root logger and HTTP logger are constructed. Invalid or case-variant input must fail startup without echoing the supplied value. Explicit `trace` must persist trace records to the file transport; `silent` is intended for isolated acceptance runs where request logs must not persist.

## Review and release policy

Both Codex and Gemini must pass the v0.3.2 candidate before publication. The operator's Gemini exception for v0.3.1 applied only to that release and does not carry forward. A blocked or unavailable reviewer remains a failed gate unless the operator makes a new, release-specific decision.

The planned server target is the existing private Ubuntu acceptance environment. Deployment must use its established SSH and loopback boundary, reuse credentials without printing or committing them, and must not rerun first-install logic against the existing database. Git promotion, a tag or a successful build cannot substitute for on-server service and health readback.

No desktop package is part of this scope. Desktop packaging or distribution is not claimed as completed.
