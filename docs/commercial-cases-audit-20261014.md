# 首页 17 个生产案例：离商业级还差什么（2026-10-14 审计）

依据：`apps/web/src/saas/production-runs/` 17 份已发布运行记录（每个节点的产出、限制、备注、浏览器验收记录）、`apps/web/showcase/` 17 张封面帧，以及画布、预览和后端代码（基线 Forgejo `main@8b1d576a`）。

## 1. 结论

17 个案例都能跑、都是 AwwO 真实生成的，但看起来是 **游戏 Jam / 技术 Demo 级**：盒子和圆柱拼的模型、平光无后期、系统字体、文字压主体、空旷构图、只读源码的"验收"。和市面上拿来展示的商业案例（Lovable / v0 的上线作品、Awwwards 品牌站、可上架的网页游戏、工业数字孪生 Demo）相比，差距是 **系统性的**：根因在平台限制，不在某个提示词。逐个改提示词重跑只能小修小补，必须先补平台能力，再按新能力重做案例。

## 2. 商业级的验收线

| 维度 | 商业级要求 |
| --- | --- |
| 视觉 | PBR 材质 + 环境光照、阴影/AO、色调映射与后期（Bloom 等）；主体是真模型或精细建模，不是几何体拼接 |
| 美术指导 | 一套贯穿全页的配色、字体、间距、动效规范；文字不压主体，有安全区 |
| 字体 | 品牌字体（国内外都能加载），层级清晰 |
| 内容 | 内容量撑得起"真产品"：关卡、数据、文案、镜头都足够 |
| 交互 | 每个按钮真实可用、状态完整（加载/空/错/完成），无明显 Bug |
| 声音 | 音乐/音效有质感，和画面同步 |
| 适配 | 桌面 + 移动/触屏都能用，60fps 预算 |
| 证明 | 画面被看过：截图验收 + 交互脚本验收，结论写进记录 |

## 4. 架构缺陷清单

### P0：不解决就到不了商业级

- **D1 每个节点只能调用一次模型，没有工具、不能执行。** 记录里 17/17 都是 `modelCallsPerNode: 1`；节点不能写文件、运行、测试、迭代。AwwO 已有托管执行（OpenMaus Docker 工作区，list/read/write/exec/publish），但只给"电脑任务"会话用，画布整图运行用不了（`graph_runs.go` 没有这条路径）。代码是"盲写"的。
- **D2 没有视觉验收闭环。** 17 个 Review 节点全部写着 "static source review, not actually run"；它们看不到画面，也不能操作。平台只有"页面报错自动修一次"。现在真正的浏览器验收是在产品外手工做的。
- **D3 输出预算太小且含思考。** 每次调用最多 32,000 tokens，思考也算在里面。页面被迫拆成 7–12K 字符的模块 + wiring + paste 三层，设计被切碎、拼接出 Bug；beat-studio、crystal-keep、neon-circuit、summer-ad 都有过 `output_limit` 或"思考耗尽一个字没写"的失败。
- **D4 渲染栈过旧且封闭。** 案例规则只允许 three.js r128（2021 年版），禁止其他脚本、字体、图片；预览只内置 r128。没有后期管线（Bloom/AO/色调映射链）、没有 GLTFLoader、没有环境贴图；r128 连 CapsuleGeometry 都要打补丁。字体只能用系统字体。

### P1：决定"像不像真产品"

- **D5 3D 资产进不了页面。** 3D 节点能生成 GLB，但页面规则是"只用预览图，不放 GLB"（`officialWorkflows.ts` `MEDIA_MODEL_PAGE`）。所以车、角色、设备全是方块和圆柱。（R1b：r186 案例的页面已能用 GLTFLoader 加载 3D 节点的模型，两个案例已换上，见 §7。）
- **D6 生成的媒体只能在 HTML 属性里用。** 预览只替换 `img/video/source/CSS url()` 里的路径（`liveDocument.ts` `URL_ATTRIBUTES`），脚本里 `TextureLoader`、`fetch`、`new Audio()` 拿不到 → 生成图不能做贴图、天空盒、精灵。也没有透明底立绘、序列帧、HDR。
- **D7 没有视频剪辑/合成节点。** 视频节点只出 5 秒片段；没有把多镜头 + 音乐 + 字幕剪成 30 秒成片的能力，所以广告案例只能交 HTML 分镜。
- **D8 没有美术指导/设计系统契约。** 每个模块各自选色选字，没有版式安全区 → 文字压主体（aurora-gt、neon-city、summer-ad、3d-configurator）。
- **D9 可靠性。** 一次模型调用失败或供应商暂时不可用就整图失败（port-twin 同一画布 4 次运行 2 次因此中止）；没有节点级自动重试/续写。
- **D15 交付页卡死会冻住整个标签页，且没人发现。** 页面跑进死循环时，iframe 和 AwwO 自己的页面在同一个渲染进程里，整页一起卡住；平台只有"报错自动修一次"，看不出"卡死"。本轮实测：EV plant r186 第一版第一帧拿到 −0.48 s 的时间步，雨淋房粒子循环 `for(n=rate(d);n--;)` 永不结束。

### P2：规模化和专业度

- **D10 展示资产存储方式。** 案例媒体以 base64 内嵌在 TS 记录里（shanhai-vn 2.4 MB、neon-city 1.4 MB），还被压缩过；封面 960×540。GLB 这类大文件放不进去。（R1b：媒体已改成静态文件，封面已升到 1280×720，见 §7。）
- **D11 移动端和性能没有验收。** 只在 1280×720 桌面测；没有触屏、竖屏、FPS 预算。
- **D12 商业级的生产流程在产品外。** 运行器、探针、录屏、验收脚本都在运营机器上（`E:\KiroCrew\…`）；用户靠画布助手做不出同等质量的方案。
- **D13 托管执行工作区本身不够用。** 无网络、无浏览器、没有预装 three/前端依赖，产物上限 8 MiB / 16 个文件；就算接到画布上，也不能构建前端工程或截图自测。
- **D14 声音。** 所有音乐音效都是 WebAudio 振荡器现场合成，没有音乐/音效生成或素材库。

## 6. 本轮实测（2026-10-15，Claude Opus 5.5，生产环境「12」工作区）

- **渲染栈换代立竿见影。** Neon Circuit r186 第一版：霓虹楼群、赛道边线、起跑门真的在发光，HUD 改成标签在上、数值在下，不再压字，桌面不再显示触屏键。也暴露了没有视觉验收的代价：雾和路面过曝发白，尾迹光带糊住镜头——模型看不到自己画了什么（D2）。
- **EV plant r186 第一版卡死整页**（D15，见上）。第二版不卡了，但启动时 `mergeGeometries` 合并了有索引和无索引的几何体，抛错后整个 3D 场景是空的，只剩面板。
- **Neon Circuit 第二版失败在声音节点**：一次 32,000 token 的调用被思考用完，`output_limit`（D3）。第一版的同一节点用了 27,308 个 token，只写了 4,945 个字符。
- **Neon Circuit 第三版：两次运行各坏在交互上。** 一次车几乎不动；另一次画面已经接近商业级（标题、霓虹城市、三圈 115 秒、对手落后 3–6 秒），但车一碰墙就永远卡住。这类问题要把赛车代码真正跑起来才看得见（我在产品外用 Node 自动驾驶跑整场、再故意撞墙），平台的静态 Review 看不出来（D2）。
- **Neon Circuit 第四版：物理对了，起跑发白。** 倒计时和起跑后约 3 秒整屏发白。原因都是数值：起跑门是白色发光条（emissiveIntensity 4），接线节点还自己在发车区挂了两盏强度 180 的点光源和一盏 300 的聚光灯。在交付页里把这几个数改小再截图，画面马上干净，于是第五版任务写明"起跑门不比路沿亮、接线不加灯"。同版另一次运行启动报错，黑屏。
- **Neon Circuit 第五版三次运行：** 一次启动报错黑屏；一次有两个节点刚要开始就被运行时拒绝（`runtime_rejected`，排队 11–14 毫秒，没有调用模型），整张图失败。三张图同时跑时，准入拒绝既不排队也不重试（D9）。第三次全部通过，已发布：60 帧，起跑清晰，自动驾驶三圈 106.4 秒，第四名，落后前三名 0.5–1.3 秒。
- **EV plant 第四、五版：从过曝到白雾。** 第四版一次运行设备节点 `output_limit`（D3），另两次白色模型整体过曝成一片白。第五版降了曝光，画面却像蒙了一层白雾，原因有两个：任务里写了"轻雾"，而正交相机在几百米外，雾把整个模型均匀刷白；泛光阈值 1.0 又低于白色表面受光后的亮度（约 1.04），白墙也在发光。在交付页里去掉雾、换一个比底座深的背景、调灯光和阈值后截图，画面立刻清晰。第六版把这些数值写进任务，三次运行全部清晰、无报错，已发布：点工位出卡片、注入故障后工位变红且上游堵塞、点车出卡片、16 倍速都验证过。
- **页面节点贴着上限跑。** EV plant 每次成功运行，页面节点都用了 28,000–29,500 个输出 token（上限 32,000，思考也算在内）；功能再多一点就会 `output_limit`（D3）。
- **发布工具也受 R1 影响。** 新的模块加载器用 Vite 的 `?raw` 方式导入文件，发布脚本用 rolldown 打包时加载不了。现在已把导入映射的常量和纯函数拆到 `previewImportMap.ts`，构建脚本不再引入加载器。
- 结论：R1 让案例画得出来；两个案例最后达到商业级，靠的是产品外的人工闭环：跑起来、截图、改数值、再跑，两个案例一共在生产环境跑了 20 次。每个视觉问题都对应一个可以测量的数（曝光、泛光阈值、发光强度、雾的距离、灯光强度），所以 R3 的视觉验收可以做成"截图 → 判断 → 调这些数 → 再截图"的自动循环；R2（续写、重试、思考预算）则是稳定出片的前提。
- **R1 的代码审查。** 请 Codex（gpt-6-astra）只读审查了六轮，共找出 20 处边界问题，全部修掉并补了测试：文件名撞上原型属性、`data:` 作用域、没报出来的导入、模块源码里的 `</script>`、根路径和绝对路径的资源、注释和懒加载导入、内联的画布 JS 模块、带本地脚本或数据文件的页面怎么路由。六轮都没有发现沙箱或 CSP 被削弱。留到以后：普通脚本里的 `import('./x.js')` 不会被内联。
- **已上线（2026-10-15 08:34 +08，`saas-6549ecad5450`，只更新网站）。** 线上未登录状态用 Chrome 打开：EV plant 和 Neon Circuit 排在最前，新封面正常；两个对话框的运行记录都是全部节点完成，交付页通过导入映射拿到 r186 的辉光后期，页面在跑、零报错；仍在 r128 上的 3D 港口驾驶舱也照常运行、零报错。部署记录见 `docs/awwo-saas-deploy.md`。这两个案例的讲解视频要按新画布重录。


## 7. R1b（2026-10-15）：品牌字体、静态媒体、3D 模型

**改了什么（只改网站）**

- **品牌字体。** 预览内置 17 个开源字体家族（OFL-1.1，取自 Fontsource 5.3.0 的拉丁子集，26 个文件共 747 KB，原样放在 `apps/web/src/canvas/fonts/`，每个家族附带它的授权）：Inter、Space Grotesk、Manrope、Outfit、Montserrat、Unbounded、Orbitron、Exo 2、Oxanium、Rajdhani、Bebas Neue、Playfair Display、Instrument Serif、Cinzel、JetBrains Mono、Press Start 2P、Pixelify Sans。页面在 font-family、style、canvas 字体串或 SVG 属性里写到哪个家族，预览就把它以 data: 来源的 @font-face 放在页面样式前面（`previewFonts.ts`）。不发任何请求，所以在国内（页面里的 Google Fonts 链接加载不了）和不联网的沙箱里效果一样。严格预览、实时页、首页案例对话框和画布成果区都生效。案例画布用 `fonts: true` 在页面规则里写明可用的字体。
- **案例媒体改成静态文件。** 三个媒体案例的图片和视频原来以 base64 写在 JS 里（`*.media.ts`，约 4.7 MB），现在按内容哈希命名，放在 `showcase/media/<案例>/`，清单在 `production-runs/<案例>.media.json`，打开对话框时才取（`loadProductionMedia`）。三个案例按原来的运行重新发布：图片改为最宽 2048 的 JPEG（原来 1600），视频改为最宽 1280、CRF 23 的 H.264（原来 960、CRF 30），运行记录逐字节不变。发布脚本现在也能发布 3D 模型节点：GLB 的几何和贴图逐字节保留，JSON 块里生成服务的标记去掉（见 D19），预览图转成 WebP。复制这类案例时，加载模型的模块和粘贴它的页面留到第一次运行再生成，因为它们记录下来的代码写的是原运行的文件路径；之前只对直接接收图片的页面这样处理。
- **3D 模型进页面。** EV plant 产线上的每辆车都是画布里 3D 模型节点生成的轿车，Neon Circuit 的六辆车都是 3D 节点生成的赛车，按车涂色。r186 的页面规则写明了 AwwO 3D 模型的约定：朝 +X、+Y 向上、居中、最长边为 1。
- **封面 1280×720。** 17 个封面全部换成 1280×720（原来 960×540）。两个新案例按新页面录制。其余 15 个重录：12 个用原来的操作脚本，在原来的位置剪；crystal-keep、mars-mission、beat-studio 换了新的操作脚本，其中 crystal-keep 手动从 12.0 s 起取 6.5 s。beat-studio 和 crystal-keep 按 960×540 的版式、1.333 倍像素比录制，输出同样是 1280×720。

**试跑。** 都用 Opus 5.5，在生产环境「12」工作区。EV plant 一个文本跑了 3 次，发布第 3 次。Neon Circuit 改了 4 个文本，共 14 次，最后一个文本 4 次全部完成，发布其中一次。另有 2 次 3D 节点探测，用来确定模型的朝向、尺寸和贴图规格。

**这一轮新发现的问题**

- **D16 模块之间交接的数据没有契约。** 两次运行里，城市模块把赛道的 signs（数组）当成对象来读。`q.at` 恰好取到数组自带的 `at` 方法，页面一打开就报错停住。这次靠在任务里写明格式解决；平台需要节点之间的结构化契约（每个交接写成 JSON Schema，交接时校验），或者 R3 的运行验收。
- **D17 3D 节点的默认产物太重。** 3D 节点的“详细贴图”是 3 张 4096² 贴图，一个模型 8–12 MB；高精度系列一个 48 MB、142 万个三角面。画布实时预览的内联上限是 24 MB，一个页面放两三个详细模型就装不下。案例改用标准贴图（2048²，约 2.5–3 MB）。平台层面：生成时另存一份网页用的版本（贴图不超过 2048，WebP），或者把文件流式传进沙箱，不再内联进 srcdoc。
- **D18 真模型和原来的灯光规则冲突。** 3D 模型的 PBR 材质（金属度 1，带金属粗糙度贴图）在没有灯光的夜景里几乎是黑的。原来“不加灯”的规则适合自发光的方块车，不适合真模型。加了半球补光以后，白色起跑线又亮到泛光阈值以上，起步时糊成一片白。这两个都是具体数值问题，再次说明 R3 的“截图、判断、调数值、再截图”闭环是必需的。
- **D19 3D 模型文件里带着生成服务的名字。** 3D 节点生成的每个 GLB，JSON 块里都写着生成服务的网址（`asset.generator`），材质、网格和节点名也以服务名开头。首页案例的 GLB 是任何人都能下载的静态文件，等于把界面上从不出现的服务名发了出去。发布脚本现在把 generator 改成 AwwO，按类型和序号重命名对象，二进制块（几何和贴图）逐字节不变，有改不掉的标记就停止发布；两个 3D 案例已按此重新发布，交付的页面不按名字查找模型里的对象，不受影响。平台层面，用户在画布里生成并下载的 GLB 仍然带着这些标记，应在 API 保存模型文件时同样处理；这一版只改网站，不涉及 API。
- **D3 又出现了。** 声音节点有 3 次运行用完了 32,000 token 的调用。一个原因是任务要求“最多 32 行、每行最多 110 个字符”，比每次实际交付的代码都短，模型反复琢磨怎么塞进去。改成 50 行以后，之后 4 次都只用了约 5,000 token。教训：任务里写死的尺寸要和真实产出相符。
- **D9 又出现了。** 同时跑 4 张画布时，运行时直接拒绝了节点（`runtime_rejected`）。运行器改成同时跑 2 张后没有再出现。
- **D15 一次没能复现的空白。** EV plant 在无头 Chrome 里连点两辆车之后，3D 画面消失，面板照常刷新，没有任何报错。同样的操作重放 4 次都没复现，可能是 GPU 上下文丢失。平台目前察觉不到这种情况。
- **字体的边界。** 只有拉丁字符（案例都是英文）。中文品牌字体要按页面用到的字切片，留到下一步。页面下载到 AwwO 之外时没有这些 @font-face，会回落到系统字体。
