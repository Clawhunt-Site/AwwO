# AwwO 行业案例体验指南

案例库默认展示 12 个「行业旗舰」。可以按行业、能力筛选，也可以搜索案例名或关键词；「基础练习」保留原来的六个入门案例。

每个案例都有三个入口：

- **体验作品**：操作浏览器内的参考实现，改变数据或约束，观察计算和状态如何联动。
- **编排画布**：查看节点职责、输入输出、验收条件和上下游交接。大图可用「节点目录」「总览」「突出依赖链」浏览。
- **复用指南**：阅读任务 brief、预期交付和边界，或下载画布 JSON。

这些是官方编写的本地参考实现，使用合成数据，不是已经接入生产系统的产品，也不是 AwwO 模型运行成功记录。下列路径按中文界面、重置后的默认样例说明；变更输入后，数值会随计算改变。切换案例或刷新页面前，请按需使用案例自身的导出功能。

## 1. KEPLER：从补给链到可回放的策略游戏

1. 将「地图种子」设为 **1701**，点「重置殖民地」。在「殖民指挥」依次于 **16 号地块建科研实验室、21 号建水培温室、22 号建氧气循环站、10 号建光伏阵列**。观察矿石、电力扣减，以及下回合资源预测。
2. 点一次「推进一回合」，在 **23 号地块建采矿站**，再推进一回合。采矿站必须位于矿脉，设施也必须接入指挥中心的连通网络才能产出。
3. 到「研究与任务」投入「高效采掘」，返回推进一回合；在 **20 号地块建居住舱**，再推进一回合。查看人口目标与食物、氧气消耗的变化。
4. 研究「辐射护盾」，再推进三回合。这条固定行动路径在第七回合达成任务；天气、储备和任务目标都参与判定，并非点击次数奖励。
5. 打开「航行记录」，点「从起点回放」。回放会从种子重做有效行动，应得到相同的回合、资源与胜负；可用「导出行动存档」保存。

**编排学习点：** 地图、经济规则与视觉可以并行设计，但可玩构建必须汇合三者。验收既要覆盖合法胜利路径，也要覆盖资源不足、离网设施和失败结局；回放提供可复现输入。

## 2. NEXUS：封路后，不能沿用旧计划

1. 在「路网与派车」选择不同车辆，查看彩色实际路径、每站到达时间与整趟载重。默认贪心计划已有一张未分配订单，不要把未分配理解为页面故障。
2. 将「道路情景」改为「E 区域完全隔离」。观察 E 点道路关闭、未分配变为两张，地图、配送明细与成本一起重算。
3. 切换「到期优先」「近点优先」，再打开「策略对比」。比较当前方案、畅通路网基线和另一策略的准点数、里程与成本；也可勾选「时窗收紧 35%」观察迟到。
4. 返回车辆面板，点「模拟派车」再点「标记路线完成」。随后改变道路或时窗，旧派车进度应清空，避免把旧路线的完成状态套到新计划上。

**编排学习点：** 路网数据、约束模型和视图分开产出，再汇合。Dijkstra 负责最短时间路径，贪心分配负责同仓、载重与时窗；验收必须保留不可达和未分配结果，不能宣称全局最优。

## 3. ATLAS：检索结果必须能回到具体版本

1. 在「证据检索」输入 **cycle-life**，查看段落分数和文档版本引用。点击结果中的来源编号，进入「版本资料室」，核对被定位的原文段落。
2. 将「访问视角」从「研发成员」改为「公开读者」。默认不纳入历史版本时，可见版本由四个变为两个；检索、实体图与声明差异只使用当前可见来源。
3. 返回「研发成员」，打开「声明复核」。查看同一声明键的不同值，点击来源核对协议和样本差异；系统标记值不同，不自动判断谁正确。
4. 在「版本资料室」修改当前语言正文，点「创建新版本并重建索引」。新版本保留旧版本；勾选「纳入可见历史版本」后可查看历史。
5. 打开「查询评测」，调整「B 标题权重」或「B k1」，比较固定查询的召回率、精确率与实际来源。不可见金标显示 N/A，不等于通过。

**编排学习点：** 先处理版本和可见范围，再建立段落 BM25 索引；实体关系、声明差异与检索结果共用来源标识。这里没有 LLM、语义向量检索或服务端权限系统。

## 4. HABITAT：同一资产连接空间和运维

1. 在「空间总览」拖动场景旋转，点击楼层，或用「选择楼层资产」选中 **C-3**。观察资产编号、温度、CO₂、人数与能耗同步切换。
2. 将「楼层切片」改为 **≤ 3 F**，可见资产从 17 个变为 11 个；切换「热力图」查看能耗或 CO₂ 分布。切片改变空间显示，不是删除园区资产。
3. 对正常资产点「注入模拟冷却故障」。观察该楼层能耗和温度上升，以及「维护队列」新增故障。
4. 点「更换阀门 · ¥1,200」或在维护队列执行维修。故障解除、相关数值回落、预算扣减；再调整「模拟时刻」「入住系数」，观察园区指标重新计算。

**编排学习点：** 几何、传感器模型与能耗模型并行定义，以稳定资产 ID 汇合；三维选择、故障和预算使用同一状态。传感器均为合成模型，没有连接真实楼宇或设备。

## 5. MERIDIAN：把订单走完，而不只改一个状态标签

1. 在「订单履约」选中 **RT-1001**，依次点「审批订单」「确认发货」。进入「库存与调拨」，观察 SH 仓商品现货减少、预留释放。
2. 返回该订单，点「整单退货入库」，再点「确认退款」。库存恢复，净收款回到零；退款不会再次加库存。「财务与事件」保留各次状态转换。
3. 在「创建购物篮」保留 SH 仓，将「城市背包」数量设为 **8**，创建草稿后点「预留库存」。可用库存不足时整单拒绝，不会先占住其他 SKU。
4. 到「库存与调拨」，从 HZ 向 SH 调拨 **3 件城市背包**，返回刚才的草稿再次预留。查看三仓库存总量不变，而订单变为「已预留」。

**编排学习点：** 商品计价、库存规则和履约状态机可以分工实现，但必须一起验收。订单先预留再审批发货；取消释放预留，退货加现货，退款只处理账单。金额按整数分计算，规则是本地商业样例，不执行支付。

## 6. FOUNDRY：先用验证集选，再显式查看测试集

1. 在「实验扫描」点「扫描六组配置」。三组逻辑回归学习率和三组树桩平滑参数产生真实训练结果，排行榜按验证 loss 排序。
2. 进入「评测与成本」，观察所选模型的验证混淆矩阵与 ROC。点「显式评估隔离测试集」，才会显示测试样本的结果。
3. 调整 FP/FN 成本，或点「使用验证集最低成本阈值」。观察阈值、混淆矩阵和成本联动；阈值改变后，旧测试展示会清空，需要重新执行测试动作。
4. 到「分布漂移」改变 CPU 特征均值偏移，比较直方图与 PSI；回到评测页点「登记当前模型卡」，在「模型登记」检查参数、数据版本和评测范围。

**编排学习点：** 数据划分先于训练，训练、评测、扫描与登记传递明确的数据版本。拟合和阈值选择不读取测试集；反复人工查看测试结果仍可能造成调参泄漏。这里训练的是浏览器内的小模型，不是大模型或云端训练任务。

## 7. FRAME：时间线修改应传导到后续制作

1. 在「剪辑时间线」选中首个画面片段，保持「波纹移动同轨后续片段」开启，将「时长 / 秒」从 **8 改为 12**。观察同轨后续片段后移四秒，项目时长和播放头范围同步改变。
2. 点「播放分镜」，或拖动「播放头」查看不同片段与图文覆盖。系统减少动态效果时，可使用播放头手动预览。
3. 在「素材与版本」检查「待授权」素材和素材版本，再看「制作校验」中的问题。启用片段引用的素材、费用和校验状态互相关联。
4. 打开「制作任务」，按前置顺序处理任务，尝试尚未满足前置条件的签核；同时调整「预算上限」，观察最终审阅与交付条件。

**编排学习点：** 分镜、素材和排期并行准备，汇合为四轨编辑与制作计划；交付节点要收到版本、授权状态和检查记录。这是分镜预演，不播放音频，也不渲染真实视频。

## 8. FORGE：设备时间和质量状态都不能跳过

1. 在「工序甘特图」选择订单，查看切割→装配→测试的实际起止时间。深色区间是非班次，同台设备不能同时承接两道工序。
2. 勾选「CUT-1 停机：第3–28小时」。默认样例完工跨度从约 **53.6h 变为 77.6h**；甘特图避开停机，迟交风险随排程更新。
3. 到「质量与交付」给已排程订单「判不合格」。整批进入隔离，「放行」不可用；重新「判合格」后才可放行。
4. 在「BOM 与物料」选择原料并「入库并重新排程」，或改变「每日班次」。观察阻塞订单与物料余量重算，旧抽检和放行结论全部失效。

**编排学习点：** BOM、工序依赖、设备日历和质量规则应分别建立，再以同一订单 ID 汇合。验收覆盖先后关系、设备互斥、物料不足不扣料，以及重排后不能沿用旧质量结论。

## 9. CAMPUS：完成先修，才开放下一门课

1. 在「课程地图」打开「回归与分类」，观察尚未满足的先修要求。初始仅「数据素养」已完成，不能直接跳到后续课程。
2. 进入「Python 与表格」，选择 **B：检查缺失原因和比例**，点「提交答案」。掌握度更新，课程完成，「质量与清洗」随之解锁。
3. 在其他可学课程尝试错误答案，再到「练习与错题」勾选「只看错题」。每轮只能提交一次；「开始新的复习轮次」会创建新的答题记录。
4. 打开「路径规划」，改变「可用分钟」和「导师席位」。观察达到目标与阶段计划的区别，并在「学习记录」核对真实答题事件。

**编排学习点：** 课程图、题库和掌握度规则并行定义；规划器枚举满足先修、时间与导师资源的组合，再输出有序计划。Beta 掌握度是练习规则，不是正式能力鉴定，也不把点击折算为学习时长。

## 10. STAY：跨夜订单必须一次检查全部库存

1. 在「房态与预订」选择「庭院大床」，入住 **10/16**、离店 **10/19**、间数 **3**，点「确认样本预订」。其中一个住宿夜库存不足，整笔拒绝，其他夜也不扣库存。
2. 将间数改为 **2** 后再确认，观察各住宿夜库存、已确认间夜和订单金额一起更新。
3. 在「订单台账」找到刚创建的订单，点「取消并回补」。对应住宿夜库存恢复，已确认间夜回到默认的 **66**；不会重复回补。
4. 打开「收益情景」，把「需求事件」改为「音乐节 · 10/18—20」。观察收入柱状图、预测入住率与方案净收入变化，再调整房价或「新增成交的直订占比」。已有订单仍保留成交价格与渠道。

**编排学习点：** 库存、定价与渠道模型分开实现，预订事务统一检查整个住宿区间；收益预测与已订收入要分开。弹性模型是教学假设，预测不等于真实可实现收益。

## 11. FLUX：成本之外，还要看守恒和缺电

1. 在「调度曲线」保持默认「峰谷电价」策略，移动「选中小时」，观察负荷、光伏、购电、充放电与 SOC 对应的数值。
2. 勾选「18–20点电网停电」。默认样例出现约 **69.6kWh 未供电量**；停电时购电为零，但逐时能量等式仍然成立。
3. 调整「储能容量」「充放电功率」或「用电需求」，查看缺口变化；在「逐时账本」核对充放电不能同时发生、SOC 不低于保留电量。
4. 打开「策略对照」，比较无储能、自用优先与峰谷电价的电费、购电峰值、碳排和缺口。较低电费未必同时带来较低碳排或更小停电缺口。

**编排学习点：** 负荷、发电和电价数据先对齐时间步长，再实现带功率、效率和 SOC 限制的调度；验收检查每小时能量守恒，不只检查汇总指标。曲线来自本地确定性规则，不控制真实电网。

## 12. CLAUSE：发现项要连到原文，而不是停在风险标签

1. 选择 **CT-201 · v2**，进入「规则发现」。点击「缺少负责人」对应的 **CT-201@2:L4**，在「证据与正文」核对 D3 行的空负责人字段。
2. 打开「版本差异」，查看 v1→v2 新增义务、日期和金额变化；这里做逐行 LCS 对照，不推断法律含义。
3. 在「履约日历」为一项义务「附示例证据」，并调整「模拟今天」。期限类提示随日期与证据变化；附证据不会消除缺负责人等正文问题。
4. 回到「规则发现」填写处理备注，改变「处理状态」；再到「审阅与导出」保存本版本审阅快照或导出 JSON。「已记录」不等于义务已履行。

**编排学习点：** 版本差异、义务规则和处理流并行建立，以合同版本和来源行汇合。新增版本保留历史，也不自动继承旧版本证据。只解析页面所示结构化条款，不提供法律结论或执行签署、付款。

## 原有六个基础练习

切换到「基础练习」可继续使用原案例，它们适合先理解单个机制，再进入行业系统。

| 基础案例 | 建议体验 | 对应学习点 |
| --- | --- | --- |
| Orbit / 团队套餐配置器 | 切换方案、人数、月付/年付，再生成本地方案摘要 | 计价纯函数与页面状态同步；月均价格和周期账单不同 |
| Signal Run / 能量路径 | 聚焦棋盘后用方向键/WASD移动，或点触屏方向按钮；收集能量再到出口 | 墙体、能量、胜负和重置组成完整游戏状态 |
| FIELD / 3D 产品展台 | 拖动旋转，切换视角、缩放和配色 | 实际三维顶点投影、背面剔除与交互参数联动 |
| Knowledge / 可溯源知识台 | 修改文档保存，再检索新词并点击来源 | 本地加权 TF-IDF 余弦检索；来源可检查，无 LLM 回答 |
| Model Lab / 训练实验室 | 调整学习率、轮数或噪声，训练后查看双集曲线与新样本预测 | 浏览器逻辑回归、训练/留出集划分与停止/重训 |
| Control / 预算审批中台 | 搜索申请，批准或填写原因驳回，再完成已批准申请 | 业务状态机、汇总预算与操作日志同步 |

## 从体验案例到自己的画布

1. 打开「编排画布」，从「节点目录」选一个构建或验收节点，查看任务、交付物和上下游交接。用「突出依赖链」确认它实际依赖哪些成果。
2. 登录后点「复制到我的画布」，或在「复用指南」下载 JSON。复制得到的是**未执行草稿**：节点、端口、依赖和验收要求已准备好，没有模型选择、历史会话或伪造的成功结果。
3. 在工作区初始化节点，使用已配置的引擎和模型；替换任务输入中的目标、数据及约束后，再运行。拥有只读权限时可以体验和下载，不能向工作区复制。
4. 检查验收节点的记录，并核对修复后的完整交付物。画布中的「检查→修复→复核」是有限的顺序依赖，不表示后端自动条件循环；未验证或未通过的项应留在交付说明中。

接入真实库存、设备、支付、传感器、文档权限或模型平台，是后续独立实施工作。首页演示的操作不会替你完成这些接入。
