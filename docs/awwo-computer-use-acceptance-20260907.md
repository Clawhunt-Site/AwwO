## 本轮发现与修复

### 已发送草稿在刷新后重新出现

真实步骤：B Session 2 发送慢请求，在流式过程中刷新；任务只执行一次，但完成后输入框重新显示已发送内容，发送按钮可用。原因是普通草稿回调在运行锁生效后拒绝保存，组件输入清空未进入持久草稿。

修复将当前手动发送会话的草稿清空与运行快照一起持久化，保留其他会话及失败前置检查时的草稿。回归先失败再通过。GUI 复验在 Session 1 留下 `UNSENT-OTHER-SESSION-MUST-SURVIVE`，Session 2 发送后立即刷新：恢复为 1/1 完成，Session 2 输入为空、发送禁用，Session 1 原草稿仍在。数据库也核对了两份草稿及恰好一次 run、一次 provider 请求。

文件：`apps/web/src/canvas/CanvasSurface.tsx`、`apps/web/tests/canvas-run-entry.test.tsx`。提交：`af4b3aa`。

### 登录错误丢失语言映射

中文页面输入错误密码，显示英文 `Invalid email or password`。Login 提前把 `SaaSApiError` 转成普通字符串，丢失了已有错误码映射需要的结构。

修复保留原始异常对象，由现有本地化函数渲染。GUI 复验显示“邮箱或密码不正确。”；同一错误切换英文后立即显示对应英文。真实表单回归还覆盖重复邮箱、非法输入、未知错误原文与切换语言不重发请求。

文件：`apps/web/src/saas/SaaSApp.tsx`、`apps/web/tests/saas-api.test.tsx`。提交：`c7548c4`。

### 局部运行的阻断数超过运行范围

只运行 B，而范围外的 A 没有可复用输出，执行正确被阻止，但汇总显示“被阻断 2（共 1）”。原因是统计把范围外上游的诊断状态也计入本次执行数量。

修复只将范围内节点计入阻断总数，仍保留范围外上游的诊断状态。缺失输出和无效输出两例回归均先失败再通过；GUI 再次使 A 的旧输出失效，从 B 的更多菜单运行单节点，显示“成功 0 · 失败 0 · 被阻断 1（共 1）”，时间线保留 A 缺少产出与 B 上游未完成的原因。此前正常局部运行也证实 B 单独执行并复用 A，不创建第二次 A 请求。

文件：`apps/web/src/canvas/runGraph.ts`、`apps/web/tests/canvas-scoped-run.test.ts`。提交：`3c52cb2`。

### 旧冲突草稿与待恢复运行并存时无法进入画布

在保留旧冲突草稿后继续运行，关闭全部 AwwO 标签页。后台 A 已完成，重新打开却停在 base 70/current 84 的恢复页：旧草稿不能覆盖新版本，而待恢复运行记录又使“使用云端版本”入口隐藏。用户只能导出或重连，无法核对真实结果。

修复提供显式“使用云端版本并核对运行（保留草稿）”入口。它保留运行记录与旧草稿；若活动缓存另有内容，则按真实本机基准另存备份，保存失败就留在恢复页。进入后由既有恢复逻辑读取已接收的任务，不自动派发下游。

GUI 在原失败数据上复验：入口可用，随后显示 A 已完成、B“页面中断前尚未下发”，汇总为成功 1、阻断 1（共 2）；A 完整历史可读。刷新后仍能分别选择 base 70 的旧稿及 base 84 的运行前备份。组件回归还覆盖读取失败保持锁定、云端输入变化不发布旧产出、备份失败保留原数据。

文件：`apps/web/src/saas/SaaSApp.tsx`、`apps/web/tests/saas-drafts.test.tsx`。提交：`e20481e`。新增四项回归修前失败、修后通过；相关 6 文件 55 项与类型检查通过，Codex GPT-5.5 和 Gemini 3.1 Pro High 均明确 PASS。

### 规划撤销后反复出现同版本草稿误报

产品模板 5 节点/5 边经规划追加为 7 节点/6 边，再撤销回 5 节点/5 边。数据库已保存 v7，界面也显示“已同步”，但刷新后反复要求恢复 base 7/current 7 的草稿。

通过真实 GUI 导出的草稿与数据库文档逐字段比对，二者所有值、数组顺序及 `updatedAt` 相同；只有五个 `threads[].outputValues` 对象的键顺序不同。撤销会补齐这些输出映射，PostgreSQL JSONB 重排对象键，直接比较 JSON 字符串便误判未同步。

修复把内容比较统一为对象键排序后的规范化 JSON，兼容旧基准记录，仍保留数组顺序、时间戳及实际字段值的差异。既有未同步草稿仍须明确处理，不能通过自动删除草稿消除提示。

GUI 在原 base 7/current 7 草稿上明确选择恢复，显示已同步；等待保存后两次刷新都直接进入 5 节点/5 边画布，规划对话仍显示“已撤销最近一次 AI 更改”，不再出现误报。这不证明编辑器撤销栈跨刷新持久化。数据库仅新增一次明确恢复保存至 v8，两次刷新没有额外保存；原运行、消息和 provider 数量不变。

文件：`apps/web/src/saas/{SaaSApp.tsx,canvasDraft.ts}`、`apps/web/tests/saas-draft-equality.test.ts`、`apps/web/tests/saas-draft-canonical-flow.test.tsx`。提交：`a42fb78`。新增 10 项比较回归和 3 项真实组件流程回归；相关 5 文件 39 项通过。双顾问均 PASS。Codex 的非阻断建议是额外显式检查旧基准字段的字符串类型；当前异常处理已安全拒绝不合法基准，未扩大本轮修复。
