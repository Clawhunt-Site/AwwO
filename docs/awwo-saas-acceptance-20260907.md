## 失败前复现与修复

1. **首次运行误报其他标签页修改。** 新节点内存省略 `lastOutput`，加载时补成 `null`，造成同一页保存后的结构指纹不同。运行前使用同一规范化流程比较。组件回归在修前观察到预期两次派发、实际零次；修后首次图运行与真正外部修改阻止派发两个案例都通过。
2. **请求等待期间的权限撤销失效。** 成员在中间件通过后等待请求体，此时被移除、降为 reader 或租户暂停，旧请求仍能写入。各业务写事务先锁租户，再读取当前成员、角色与租户状态。33 个端点与撤权组合通过；取消状态、事件及审计纳入同一授权事务，重复取消不新增审计。
3. **SSE 历史回放绕过周期鉴权。** 大批历史事件持续回放时没有进入空闲心跳分支，撤权后仍可读取后续历史。每批及事件写出前检查期限；释放数据库连接后再网络写出和重新鉴权。成员移除、logout、会话过期三类回放回归通过。默认鉴权间隔仍为 15 秒，不承诺即时撤销已发送数据。
4. **数据库运行锁丢失后仍接受任务。** 请求体或 Pi 健康检查等待期间，测试专属 lease 连接已断开且监控确认失锁，旧请求仍返回 202 并留下 queued run。事务取得租户锁后及 run/规划提交前复查 worker 可用状态；两个真实 PostgreSQL 故障注入场景修后均返回 503，任务、用户消息与 Pi 调用均为零。未终止其他连接；该检查不构成多副本 fencing，也不消除物理失锁检测与最后检查到提交之间的瞬时窗口。
5. **畸形 HTTP 目标导致 Pi 服务退出。** 原生 HTTP 请求目标 `//`、`http://[`、`http://` 触发未捕获 URL 解析异常。现在返回 400 `INVALID_REQUEST_TARGET`；后续健康、鉴权及路由请求证明同一个进程存活。
6. **本地启动中止后仍启动服务。** Go 编译期间收到 SIGTERM，编译返回后仍会启动三个服务。启动器在各异步阶段及进程启动边界检查停止状态，串行清理晚返回的自有资源。行为测试覆盖中止、启动失败与正常生命周期，保留复用 PostgreSQL。

对应文件：`apps/web/src/canvas/CanvasSurface.tsx` 及运行入口回归；`backend/internal/app/{app,invitations,resources,planning,runs}.go` 及授权/lease 回归；`apps/pi-worker/{server,worker.test,http-boundary.test}.mjs`；`scripts/awwo-saas-{dev,scripts.test}.mjs`。
