## 二、SuperClaw 本身的架构

### 当前双服务端架构（Leon 最新方案）

```
用户浏览器 (React 前端, port 5180)
    │
    ├─ /api/chat/*  ──────────→  Node Server (port 3810)
    │  /api/workspaces/*           Paperclip agent runtime
    │  /api/backends/*             负责: chat 对话引擎
    │  /api/agents/*
    │  /v1/skills/*
    │
    └─ 其他所有路由  ──────────→  Python Server (port 8810)
       /api/runs/*                 FastAPI + 原有核心引擎
       /api/goals/*                负责: 团队管理、插件、运行、
       /api/team/*                        评估、市场等全部其他功能
       /api/plugins/*
       ...
```

### 为什么是双服务端？
- Leon 之前自研 Python 后端，开发周期太长
- Paperclip (Pi) 有成熟的 agent runtime 调度器（heartbeat → adapter.execute）
- 想直接用它的 chat 能力，但 Python→Node 全量迁移成本太高
- 折中方案：Node 管 chat，Python 管其他，Vite proxy 分流

## 五、Windows 开发环境评估

### 硬性阻断（Python 内核）
| 问题 | 文件 | 影响 |
|---|---|---|
| `os.getuid()` 不存在 | workspace_resolver.py | **启动即崩** |
| `import fcntl` 无条件导入 | relay_key.py | **导入即崩** |
| `fcntl + select` 在 pipe 上 | backends.py | ClawWork RPC 崩 |
| daemon AF_UNIX 仅 POSIX | daemon.py | daemon 不能启动 |
| `os.kill(pid, SIGTERM)` | cli.py | 进程管理崩 |
| POSIX 权限位折入签名摘要 | trust.py | 跨平台签名不一致 |

### 可以工作的部分
- ✅ Node 服务端（Paperclip）— 跨平台
- ✅ React 前端 — 跨平台
- ✅ 所有 pip 依赖都有 Windows 轮子
- ✅ 部分模块已有 Windows 兼容分支

### 推荐方案
| 方案 | 优先级 | 说明 |
|---|---|---|
| **WSL2** | ⭐⭐⭐⭐⭐ | 最省事，完整 Linux 环境，所有东西直接跑 |
| Docker Desktop | ⭐⭐⭐⭐ | 项目有 docker-compose.yml |
| 修 Python Windows 崩溃 | ⭐⭐⭐ | 改 3-5 个文件，有现成模式可参照 |
| 只开发 Node + 前端 | ⭐⭐⭐ | 不碰 Python 崩溃点 |

## 六、核心诉求分析：网页版拉通联调

### "网页版"是什么？
SuperClaw 有两个"网页版"概念：

1. **独立工作台** (`apps/web/`) — SuperClaw 自己的 React 前端
   - 完整的团队管理、chat、运行监控、设置面板
   - 独立运行在 localhost

2. **嵌入到 ClawHunt** (`superclaw_embed/`) — 作为 ClawHunt 的子服务
   - 多租户，每用户独立
   - 嵌入到 https://clawhunt.store/superclaw
   - **这是线上产品需要的**

### 核心工作路径

```
第一阶段: 确认 SuperClaw 独立能跑
├── 搭环境 (Docker / WSL2)
├── 启动双服务端 (Node + Python)
├── 浏览器端到端验证 (Leon 的第 10 步)
└── 确认 chat 能真正跑通

第二阶段: SuperClaw ↔ ClawHunt 联调
├── bump superclaw.lock 到合适版本
├── 前端嵌入 (React 子路由 + JWT)
├── 真 relay key 测试 (出真答案)
└── 端到端: 用户在 ClawHunt 里用 SuperClaw 聊天

第三阶段: 优化与交付
├── 性能优化
├── 完整测试通过
└── 部署上线
```

## 七、立即可做的事

### 环境准备（选一个）
```bash
# 方案 A: Docker (你说已经开了)
cd SuperClaw
docker compose up                    # 启动 superclaw-api (Python + React)

# 方案 B: WSL2 (推荐，最完整)
wsl --install                        # 安装 WSL2
# 进入 WSL 后:
git clone https://github.com/ClawHunt-Store/SuperClaw.git
cd SuperClaw
python3 -m pip install -e ".[dev]"
npm install --prefix apps/web

# 方案 C: 原生 Windows (只跑 Node + 前端)
git checkout node
cd server && pnpm install && pnpm -r build
pnpm dev                             # Node server :3810
cd ../apps/web && npm install && npm run dev  # React :5180
```

- [ ] SuperClaw Python API 能启动 (`/health` 返回 200)

- [ ] React 前端能打开
